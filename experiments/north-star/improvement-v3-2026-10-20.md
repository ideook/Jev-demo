# 남은 보고 누락과 전환·복귀 보강

2026-10-20. [2차 개선](improvement-v2-2026-10-20.md)에서 남았던 실제 보고 누락 C02와 사용자 전환 H14·복귀 H17을 대상으로 수정하고 검사했다.

**전환·복귀는 새 실제 API 평가에서 올바른 분류와 비공개 갱신 안내로 연결됐다. 남은 보고 누락은 동일 요청의 저장 판단을 재생하면 내부 검토로 연결된다.** 사용자에게 정정을 실제 추가한 성공 사례를 뜻하지 않는다.

## 변경

사용자 메시지의 관계 질문을 에이전트 작업과 분리했다. 사용자에게는 continue / user_switch / return / insufficient만 묻고, 에이전트의 무단 이탈은 Stop의 작업 관계 질문에서 판단한다. 응답 확률 목록도 이벤트별 선택지와 정확히 일치해야 한다.

사용자가 명시적으로 계획을 보류하면 공통 도구를 사용한다는 이유만으로 하위 작업으로 보지 않는다. 다른 기록된 목표의 다음 단계로 돌아가는 것도 복귀로 본다. continue는 내부 공통 형식의 on_track으로 정규화한다.

전환과 복귀의 개별 신뢰도가 낮더라도 두 확률 합계가 0.8 이상이면 비공개 목표 정리만 요청할 수 있다. 원문 근거 0.8 조건은 유지한다. 훅이 실제 목표를 자동 변경하거나 사용자에게 이전 목표를 강요하지 않으며 Codex가 원문을 확인한다.

보고 누락 질문에는 앞선 구현·설치·복구와 뒤늦은 검증의 연결을 명시했다. 재요청은 같은 작업의 연속이며, 사용자가 답변 범위를 별도로 제한하지 않았다면 검증 결과가 무엇을 완성했는지 짧게 연결해야 한다. 서비스 상태·파일 지문 일치만으로 앞선 성과를 설명했다고 계산하지 않는다.

추가한 제한적 재검토 조건은 다음과 같다.

- Stop이고 활성 계층의 완료 내역과 사용자·assistant 원문이 있다.
- 원문 근거가 0.8 이상이며 원문은 잘리지 않았다.
- 마지막 사용자 메시지 전체가 지원하는 독립적인 재시도·재요청이다. 인용·부정·복합 제한을 부분 문자열로 인식하지 않는다.
- 결과 보고로 분류됐고 누락 점수가 0.5 이상이다. 명확한 좁은 답변·진행 보고와 전환·복귀에는 적용하지 않는다.
- 앞선 성과와 이번 검증을 연결하는 완결된 긍정 문장이 이미 있으면 이 약한 신호 경로를 사용하지 않는다.

0.5는 누락 확정 기준이 아니라 원문을 확인할 불확실성의 기준이다. 기존 0.8의 강한 누락·모순 검사는 그대로 적용한다. 한 번의 내부 확인·15분 억제·재진입 차단을 공유하며 새 작업·배포·추가 API 요청을 허가하지 않는다.

긍정 연결문 보호는 지원하는 제한된 한국어·영어 문장 형식만 인식한다. 인용·부정·조건·미래 계획을 완료 문장으로 보지 않는다. 이 문장 검사는 실행 성공을 증명하지 않고, 강한 누락·모순 신호를 덮어쓰지도 않는다.

## 실제 평가와 정책 재생

먼저 기존과 동일한 비식별 사례 30개를 각 1회 평가했다. 그 뒤 사용자 허용을 받아 C02에서 만든 합성 대조 2개를 각 1회 평가했다. 새 원본 대화는 추가하지 않았다. 총 **32회**, 재시도 없음. 처음 대조 2개 전송이 자동 승인 검토에서 차단됐을 때 요청은 실행되지 않았다.

모델은 비교를 위해 기존 North Star의 jev-1.13.0을 유지했다. 입력 85,874토큰, 출력 5,365토큰. API 왕복 189–311ms, 합계 6,909ms다. 네이티브 훅 전체 지연이나 향후 지연 보장은 아니다.

| 대상 | 2차 개선 후 | 이번 실제 API 결과 | 최종 정책 재생 |
| --- | --- | --- | --- |
| C02, 재요청 후 앞선 설치·복구 연결 누락 | 통과하며 놓침 | 누락 0.60이지만 통과 | **내부 검토** |
| H14, 계획 보류 후 새 목표 | 보류 | **전환·내부 갱신** | 동일 |
| H17, 이전 목표의 다음 단계로 복귀 | 보류 | **복귀·내부 갱신** | 동일 |
| H19, 앞선 성과 부정 | 내부 검토 | **내부 검토** | 동일 |

H14는 user_switch, 전환·복귀 확률 합계 0.83이었다. H17은 return, 합계 0.93이었다. 선택지별 신뢰도는 각각 0.51·0.29였으므로 특정 목표를 강제 선택할 확신이라고 해석하지 않는다. 같은 비공개 정리 동작에 해당하는 두 확률을 합한 것이다.

정상 실제 사례 19개는 **정상 통과 17·판단 보류 2·불필요한 보완 요청 0**이었다. 이전은 정상 통과 16·보류 3이었다. 정상 사례의 보류를 의미 분류 정답으로 계산하지 않는다.

기존 좁은 질문 대조는 이번에 정상 통과 대신 보류했으나 개입하지 않았다. 근거가 약한 가상 누락 D04는 여전히 보류다. 정답을 정하지 않은 탐색 사례는 성능 분모에서 제외했다.

### 추가 대조에서 발견하고 고친 오탐

R01은 C02 답변 앞에 앞선 설치·복구를 이번 조회로 검증했다는 연결문을 추가했다. R02는 사용자 요청을 앞선 설명은 생략하고 재요청 조회 결과만 달라는 좁은 요청으로 바꿨다.

| 합성 대조 | 실제 평가 시 정책 | 최종 정책 재생 |
| --- | --- | --- |
| R01, 필요한 연결문이 있는 올바른 답변 | 누락 0.52로 불필요한 내부 검토 | **정상 통과** |
| R02, 명시적으로 좁힌 질문 | 정상 통과 | **정상 통과** |

R01의 오탐을 본 뒤 완결된 긍정 연결문 보호를 추가했다. C02는 내부 검토로 보내면서 R01·R02는 조용히 통과하는 것을 저장 판단과 회귀 검사로 확인했다.

**정책을 고친 뒤 새 모델 호출로 결과를 재측정한 것은 아니다.** 대신 32개 모두 현재 코드가 만드는 공급자 요청의 전체 SHA-256이 실제 요청과 일치하는지 검사했다. 질문·입력이 같을 때만 저장 판단을 정책 재생에 사용한다. 선택지 스키마가 달라진 과거 판단을 새 질문에 그대로 재사용하지 않는다.

기존 30개와 새 대조는 수정에 사용한 개발 자료다. 일반적인 정확도·독립 평가 성능·실제 자동 정정 성공률을 주장하지 않는다.

## 검증과 적용

전체 Python **165개 통과**. 새 16개 검사는 인간용 관계 스키마, 응답의 이벤트별 검증, 비공개 유지 동작, 원문·범위 조건, 재요청·긍정 연결문 보호, 억제·재진입, 공급자 요청 해시와 정책 재생 무호출을 포함한다. 유료 API를 테스트 스위트에서 호출하지 않는다.

최종본을 **실제 전역 설치에 반영했다**. 샌드박스 설치와 설치본 핵심 검사 **14개**가 통과했고 소스·설치본·manifest·정책 재생의 코드 해시가 일치한다. 실제 설정과 훅 정의는 --preserve-config로 바이트 단위 보존했다. 네이티브 훅 **10개 모두 enabled/trusted**, 경고·오류 없음.

최종 백업은 ~/.codex/north-star/backups/20261020T124506823154Z에 있다. 추가 대조의 오탐을 고치기 전 설치 증거도 pre-guard 파일로 보존했다. 유효한 누락을 네이티브 Stop에서 실제 자동 정정하는 전체 동작은 아직 관찰하지 않았다.
