# North Star + Jev: Codex 작업 연속성

2026-10-20. 긴 작업에서 상위 목표와 하위 작업을 유지하고, 요청하지 않은 이탈이나 최종 보고의 상위 성과 누락이 있을 때만 짧게 복구하도록 구현했다. 실제 Codex 전역 설치와 사용자의 네이티브 Trust 승인까지 완료했다.

후속 [긴 실제 대화 평가](history-evaluation-2026-10-20.md)에서는 10월 8–20일 로그를 분석하고
비식별 사례 30개를 실제 평가했다. 정상 사례 19개에서 불필요한 보완 요청 1개,
실제 보고 누락 2개에서 모두 판단 보류가 나왔다. 보류와 정상 분류를 구분했으며,
주제 유지 연속 구간 3개와 원본 길이 제한 재생 결과도 기록했다.

이후 [2차 개선 결과](improvement-v2-2026-10-20.md)에서는 같은 사례 30개를 추가 평가했다.
정상 사례의 불필요한 보완은 1→0개, 정상 통과는 4→16개로 바뀌었다.
최종 정책 재생에서 실제 누락 1개가 내부 검토로 전환됐지만 다른 1개와 전환·복귀 판정은 여전히 미해결이다.
수정본은 전역 반영했고 Python 149개·설치본 핵심 검사 10개가 통과했다.
설정과 훅 정의는 그대로이며 전체 10개 훅이 enabled/trusted다.

[3차 개선](improvement-v3-2026-10-20.md)에서는 남은 누락과 전환·복귀를 보강했다.
전환·복귀는 실제 평가에서 비공개 갱신으로, 누락은 동일 요청의 저장 판단 재생에서
내부 검토로 연결됐다. 정상 19개에 불필요한 보완은 없었고, 추가 대조에서 발견한 오탐도
긍정 연결문 보호로 수정했다. 실제 평가 32회와 정책 재생을 구분해 기록했다.
최종본 전역 반영, 전체 165개·설치본 14개 검사와 기존 설정·훅 정의 보존을 확인했다.

## 구현

- [상태·훅 코드](../../hooks/north-star/north_star.py): 대화별 목표 계층, 원문 참조와 해시, 이전 목표 버전, 완료·남은 작업, CAS, 중복 억제, 제한된 Jev 호출.
- [Codex 스킬](../../skills/north-star/SKILL.md): 원문에 근거한 목표 정리, 하위 작업·명시적 전환·복귀 처리, 실제 결과를 연결하는 최종 설명.
- [설치기](../../scripts/install_north_star.py): 다른 훅을 보존하고 사용자 범위 스킬과 SessionStart, UserPromptSubmit, Stop, PreCompact, PostCompact를 설치한다.
- [오프라인 계약 검사](../../tests/test_north_star.py)와 [평가 도구](evaluate.py): 합성 자료와 모의 판단이 기본이다. 실제 API는 별도 `--live`가 필요하다.

Jev는 관계 Choice, 원문 근거 Noul, 상기 필요 Noul, 관련 보고 누락 Noul, 보고 범위 Choice, 성과 부정 Noul을 한 요청에서 독립적으로 판단한다. 목표 문장이나 실행 성공 판정은 만들지 않는다. 코드가 원문·상태를 관리하고 Codex가 의미와 실행 증거를 확인한다.

정상 진행과 하위 작업에는 사용자 메시지를 추가하지 않는다. 명시적 새 주제·복귀는 내부 목표 갱신 요청만 전달한다. 압축 전후에는 상태를 보존하고 SessionStart에서 조용히 복원한다. 압축 자체는 상기 사유가 아니다.

## 설치와 검사

Python 3.12 이상, macOS/Linux용이다. 파일 잠금에 `fcntl`을 사용한다.

```sh
python3 -m unittest discover -s tests -v
node --test hooks/jev-belay/codex.test.mjs
git diff --check

# 격리 설치. 외부 전송은 기본 비활성.
python3 scripts/install_north_star.py \
  --codex-home .runtime/experiments/north-star/codex-home

# 허용된 전송 범위로 실제 사용자 Codex에 설치.
python3 scripts/install_north_star.py --allow-export

# 기존 전송 동의·모드·맞춤 설정을 바이트 단위로 보존하며 코드/스킬만 갱신.
python3 scripts/install_north_star.py --preserve-config

# 합성 사례 준비만 수행, API 호출 없음.
python3 experiments/north-star/evaluate.py \
  --output .runtime/experiments/north-star/cases.json

# 전송·호출 범위를 별도로 허용한 평가에서만 사용.
python3 experiments/north-star/evaluate.py --live \
  --cases .runtime/experiments/north-star/cases.json \
  --max-calls 23 --output .runtime/experiments/north-star/evaluation.json
```

새 훅은 Codex `/hooks`의 Trust 절차를 거쳐야 한다. 설치기는 신뢰 기록을 만들거나 우회하지 않는다. `--allow-export` 없이 재설치하면 외부 전송이 비활성화된다.

실제 설치 위치는 `~/.codex/north-star/`, 스킬은 `~/.codex/skills/north-star/`다. 다른 `CODEX_HOME`을 사용하면 해당 루트에 설치된다. 기존 TypeSafe 환경변수 또는 `~/.config/typesafe/env`를 읽으며 키를 복사하지 않는다. 파일별 SHA-256과 백업 경로는 `north-star/installation.json`에 남긴다.

## 같은 날 후속 보강: 불확실한 보고 범위 재검토

전체 결과를 명확히 요구한 경우에도 보고 범위 분류가 불확실하면 높은 누락 신호가 묻히는 경로를 보강했다. 기존 정책을 전반적으로 느슨하게 하지 않고 다음 조건을 모두 만족할 때만 **비공개 검토**로 넘긴다.

- 활성 목표 또는 그 상위 목표에 근거가 연결된 완료 내역이 있다.
- 원문 근거 점수 0.8 이상, 누락 점수 0.8 이상, 보고 범위 신뢰도 0.8 미만이다.
- 마지막 사용자 메시지 전체가 “전체 작업 결과를 설명해줘”처럼 지원하는 단독 전체 결과 요청이다. 인용·부정·추가 제한이 있는 복합 문장은 부분 문자열로 판정하지 않는다.
- 주제 전환·복귀 분류가 아니며, 신뢰도 높은 좁은 질문·진행 보고 판정을 덮어쓰지 않는다.

이 분기는 자동 정정을 확정하지 않는다. Codex가 사용자 요청, 앞선 성과 근거, 이미 표시한 답변을 한 번 확인하고 실제 누락일 때만 짧게 보완한다. 검토 사실을 사용자에게 따로 알리거나 작업을 재개하지 않는다. 확인할 수 없거나 의도된 좁은 답변·진행 보고이면 조용히 종료한다. Stop continuation 자체는 내부 처리 시간과 모델 비용을 추가할 수 있다.

기존 보고 보완과 15분 억제 구간을 공유하고 재진입·중복 이벤트는 다시 호출하지 않는다. Jev 질문·요청 본문·API 호출 예산·외부 전송량은 늘리지 않았다. 아직 지원하지 않는 표현이나 복합 요청은 기존 보수적 정책을 따른다.

Codex 스킬에도 최종 결과를 쓰기 전 상위 성과와 남은 작업을 조용히 대조하고, 완료 주장은 실제 실행 근거를 확인하도록 추가했다. 새로운 네이티브 ‘답변 전 훅’이나 실행 증거 수집기를 구현한 것은 아니다.

**검증:** Python **113개 통과**(North Star 79개, 기존 34개). 새 10개 검사는 기록된 누락 사례, 좁은 질문으로의 후속 제한, 인용·부정·복합 문장, 다른 주제의 완료 내역, 근거 부족, 주제 전환, 재진입, 중복, 억제 구간과 shadow 동작을 포함한다. 기존 12개 판단을 재생하면 놓친 1건만 `abstain → review`로 바뀌고 나머지 11건은 동일하다. **이는 재검토 경로의 개선이며, 12/12 탐지 정확도나 실제 정정 성공을 뜻하지 않는다.** 이 후속 보강에서 새로운 유료 API 평가는 수행하지 않았다.

관련 자료: `.runtime/experiments/north-star-20261020/improvement-tests.log`, `improvement-replay.json`. 앞 절의 103개 검사와 뒤의 의미 평가 수치는 최초 적용 시점의 결과로 보존한다.

수정본은 전역 설치에 반영했다. 설치된 모듈로 핵심 회귀 4개를 다시 실행해 통과했고, 소스·설치본·manifest 해시가 일치한다. `hooks.json`은 변경 전 백업과 바이트 단위로 동일하며, 네이티브 목록에서 전체 10개 훅의 enabled/trusted 상태와 North Star 스킬 enabled를 다시 확인했다. `improvement-installed-tests.log`, `improvement-file-verification.json`, `improvement-verification.json`에 증거를 남겼다. 새 비공개 검토가 실제 대화에서 정정까지 이어지는지는 별도 관찰이 필요하다.

## 의미 판단 평가와 놓친 사례

23개 합성 사례와 3개 비식별 실제 발췌를 사용했다. 합성 사례에는 정상 진행, 하위 수리·검증, 사용자 전환, 완료 후 새 작업, 이전 주제 복귀, 이탈, 보고 누락, 좁은 상태 질문, 진행 보고, 인용 지시, 근거 부족, 압축 후 계속하기가 포함된다.

실제 발췌는 앞선 구현·설치를 마지막 조회 결과만으로 축소한 보고 1건, 특정 상태만 묻는 정당한 좁은 질문 1건, 상위 결과와 후속 검증을 함께 설명한 정상 보고 1건이다. 사용자 원문과 앞선 assistant 성과 보고를 함께 사용했다. 뒤늦은 정정은 정답 검토에만 사용했으며 판단 입력에는 넣지 않았다. 이름·경로·주소·식별자는 비식별화했고 전체 로그나 도구 출력은 보내지 않았다.

초기 26회, 판단 문구 보정 8회, 누락 기준 보정 5회, 보고 범위를 분리한 최종 개발 세트 12회, 설치본 합성 검사 1회로 **통제된 유료 평가 총 52회**를 수행했다. 입력 75,254토큰, 출력 6,763토큰. API 왕복 측정 184–276ms, 합계 10,594ms. 훅 전체 실행시간이나 향후 지연을 보장하는 수치는 아니다.

최종 12개 개발 사례의 저장된 판단에 현재 정책을 재적용하면 **11개가 기대 동작**, **보고 누락 1개는 판단 보류로 놓침**, 불필요한 사용자 상기 0개였다. 정상 사례의 판단 보류는 사용자에게 조용히 유지된다는 동작만 맞은 것으로 계산했다. 이를 의미 분류 성공이라고 계산하지 않았다.

놓친 사례는 앞선 구현·설치가 있었는데 “이번 전체 작업은 파일 한 개를 읽어 본 것뿐”이라고 보고한 합성 입력이다. 누락 점수는 높았지만 보고 범위를 진행 보고로 낮은 신뢰도로 분류해 보완 조건을 통과하지 못했다. 실제 과거의 상위 보고 누락 사례는 현재 정책에서 보완 대상으로 잡혔다.

**이 11/12는 같은 자료에 맞춘 개발·정책 재생 결과이며 독립 평가 정확도가 아니다.** 새 대화에 대한 탐지 보장은 없다. 원문이 모자라거나 잘리면 자동 보완보다 판단 보류를 선택한다.

## 판단 정책과 전송 경계

일반 개입은 원문 근거 점수 0.8 이상을 전제로 한다. Stop은 현재 목표 계층만 검사한다.

- 이탈: 관계 신뢰도 0.8 이상, 상기 필요 0.8 이상.
- 보고 누락: 활성 목표 또는 그 상위 목표에 완료 내역이 있고, 관련 누락 0.8 이상, 결과 보고 범위 신뢰도 0.8 이상.
- 성과 부정: 같은 범위의 성과 부정 0.8 이상이면 비공개 검토. 확실한 정정이 아니다.
- 불확실성 검토: 누락 0.8 이상·범위 신뢰도 0.8 미만일 때 결과 보고 선택 또는 명시적 전체 결과 요청이 있으면 비공개 검토.
- 결과 설명 요청: 지원하는 독립 “뭘 한 거야?” 질문, 완료 내역과 사용자·assistant 원문이 있고 근거·성과 부정 각각 0.5 이상이면 로컬 재검토만 요청한다. 전환·복귀·잘린 원문에는 적용하지 않는다.
- 명시적 전환·복귀: 관계 신뢰도 0.7 이상에서 내부 갱신 안내. 사용자 상기는 하지 않는다.
- 전환·복귀 사이에 판단이 나뉜 경우 두 확률 합계 0.8 이상이면 내부 정리만 요청할 수 있다. 인간용 관계 질문에는 에이전트 이탈 선택지를 넣지 않는다.
- 독립 재요청 뒤 결과 보고: 완료 내역과 사용자·assistant 원문, 근거 0.8 이상·누락 0.5 이상이면 비공개 검토한다. 명확한 좁은 답변·진행 보고와 이미 긍정 연결문이 있는 약한 신호는 제외한다.
- 정상 진행·하위 작업: 둘 중 하나를 선택하고 두 확률 합계 0.8 이상이면 조용히 유지한다.

점수는 보조 신호다. 비공개 검토는 원문 재확인 요청이며 실제 누락·실행 성공을 뜻하지 않는다.

전송은 고정 HTTPS TypeSafe endpoint 한 곳이다. 대화별 시간당 최대 24회, 재시도 없음, 네트워크 제한 8초, 네이티브 훅 제한 12초. 목표 각 300자, 선택 원문 각 1,200자, 최근 대화 최대 6개 각 1,200자, 중복을 제외한 현재 메시지 2,000자, 전체 상태 24,000 UTF-8바이트 이내다. 완결된 기계 인용 푸터만 제외하며 본문 조건은 보존한다. 원문·현재 메시지가 잘리면 판단하지 않는다. 전송 전 보류는 호출 예산을 사용하지 않지만 실패·결과 불명 네트워크 요청은 사용한다. 임의의 인명은 완벽하게 제거할 수 없으므로 비식별화 보장을 주장하지 않는다.

단일 대화 상태는 최대 32개 목표다. 원문 경로·바이트 위치·해시·역할·범위를 검사하며 타 대화의 원문이나 위임 메시지를 이 대화의 인간 원문으로 대신 쓰지 않는다. 따라서 다른 대화에서만 승인된 위임 작업은 전체 목표 자동 복원이 제한된다. 이번 대화에는 직접 받은 신뢰 승인 답변에 근거한 검증 목표만 기록했다.

## 복구와 운영 한계

상태는 `north-star/threads/<thread-id>/state.json`, 이전 의미 버전은 `history/`, 내용 없는 판단 감사 기록은 `audit.jsonl`이다. 업데이트는 `anchor --expected-version`으로 수행한다. 스킬이 원문을 읽고 목표를 유지하지 않으면 훅이 목표를 대신 만들어내지 않는다. 원문 이동·수정·미지원 transcript 형식·API 오류는 작업을 막지 않고 판단을 생략한다.

동일 이벤트는 중복 처리하지 않는다. 같은 목표 버전·판단의 상기는 15분간 억제하며 공급자 오류 뒤에는 60초간 호출을 쉬게 한다. 압축으로 이 간격이 초기화되지 않는다. fork는 별도 상태를 사용한다.

Stop은 이미 표시한 답변을 고칠 수 없다. 보고 누락 조건을 만족하면 최대 한 번의 짧은 정정을 위한 continuation을 요청한다. Codex가 원문을 다시 확인해야 하며, 새 작업·배포·권한 확대를 허용하지 않는다. 재진입 Stop은 무시한다. 그 밖의 Stop 이탈 판단은 다음 사용자 프롬프트에서 새 요청과 다시 비교한다.

일시 중지하려면 `north-star/config.json`의 `mode`를 `off`로 설정한다. 판단만 관찰하려면 `shadow`, 조건부 안내를 사용하려면 `conditional`이다. 파일을 삭제할 필요가 없다. 복구 시에는 `installation.json`이 가리키는 백업에서 해당 North Star 파일을 비교·복원하고, 기존 `hooks.json` 전체를 덮어쓰기 전에 이후 추가된 다른 훅이 있는지 확인한다.
