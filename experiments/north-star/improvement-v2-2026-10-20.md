# 실제 이력 평가 후 2차 개선

2026-10-20. [이전 평가](history-evaluation-2026-10-20.md)의 오탐·누락·길이 제한을 개선했다.

**같은 정상 사례 19개에서 불필요한 보완 요청은 1→0개, 정상 통과는 4→16개가 됐다.** 실제 보고 누락은 새 API 비교에서는 여전히 2개 모두 놓쳤다. 이후 명시적인 결과 설명 요청의 불확실한 모순을 내부 검토하는 정책을 추가했고, 저장된 판단을 재생하면 그중 1개가 검토 대상으로 바뀐다. 나머지 1개는 아직 놓친다.

이 자료는 개선에 사용한 개발 세트다. 독립 정확도나 실제 정정 성공률로 계산하지 않는다.

## 변경 내용

**보고 범위와 성과의 종류를 바로잡았다.**

- Stop 입력은 활성 목표와 상위 목표만 포함한다. 별개로 끝난 주제는 보고 의무에서 제외하고 사용자 복귀 판단용으로 보존한다.
- 누락 질문은 이번 답변에 필요한 성과를 묻는다. 조사·문서·평가 성과에도 적용하며 구현·설치를 무조건 요구하지 않는다.
- 관련 누락 기준은 0.55→0.8로 강화했다. 마지막 조회 결과만 말하는 것과 필요한 상위 성과를 설명하는 것을 구별한다.
- 기존 정상 진행·하위 작업 사이의 확률 분산 때문에 보류하지 않도록 두 확률을 합한다. 합계 0.8 이상이면 조용히 유지한다. 이탈·전환 기준을 일괄 낮춘 것은 아니다.

**성과 부정은 독립적으로 검사한다.**

- 한 요청에 여섯 번째 Noul 질문을 추가했다. 같은 대상·같은 작업 범위에서 앞선 성과를 부정하는지를 묻는다.
- 정상 근거 점수 0.8 이상·성과 부정 0.8 이상이면 한 번 내부 검토한다. 좁은 질문이어도 같은 성과를 부정하면 확인 대상이 된다.
- 별도 대상·아직 안 한 단계·이번 검증 중 추가 변경이 없었다는 설명·단순 인용은 성과 부정과 구분한다.
- 필요한 성과 누락이 0.8 이상이고 결과 보고를 선택했지만 범위 신뢰도가 0.8 미만이면 내부 검토한다. 확실한 좁은 답변·진행 보고는 덮어쓰지 않는다.

**사용자가 무엇을 했는지 직접 묻는 경우의 불확실성을 처리한다.**

새 API 결과에서 H19가 다시 보류된 뒤, 별도의 제한된 정책을 추가했다. 지원하는 독립 질문인 “뭘 한 거야?”와 선택적인 “그냥 … 한 거야?”처럼 사용자가 결과 설명을 요구했을 때만 적용한다.

조건은 Stop, 활성 계층의 완료 내역, 같은 계층의 사용자·assistant 원문, 원문이 잘리지 않았음, 주제 전환·복귀가 아님, 근거와 성과 부정 점수 각각 0.5 이상이다. 0.5는 확신이 아니라 **불확실성을 확인할 필요**라는 뜻이다.

이 경로는 Codex가 원문을 다시 읽도록 요청한다. 자동 정정·성공 확정·외부 API 재호출·작업 재개를 허용하지 않는다. 기존 15분 억제와 Stop 재진입 방지를 공유한다. 지원하지 않는 질문·인용·부정·추가 제한이 있는 복합 문장은 추측해서 인식하지 않는다.

**긴 입력과 기계 메시지를 정리했다.**

- 현재 답변을 최근 메시지에 중복 넣지 않는다. 2,000자 현재 답변 한도는 유지한다.
- 본문 뒤에 완결된 형식으로 붙은 메모리 인용 푸터만 제거한다. 뒤에 조건 문장이 있거나 형식이 불완전하면 제거하지 않는다.
- 질문 답변 포장 형식에서는 사용자의 `answer`만 판단에 사용한다. 원본 기록과 참조 위치·해시는 바꾸지 않는다.
- `<hook_prompt ...>`는 인간의 원문 근거에서 제외한다. 직전 정상 보고 후 실제 Stop 훅이 오탐으로 보낸 긴 안내가 사용자 요청처럼 다시 들어가는 문제를 막는다.
- 오래된 본문·선택 원문은 여전히 각 1,200자 제한을 적용한다. 조건 문장을 임의로 잘라 판정을 진행하지 않는다.
- 잘린 입력·키 없음·오래된 스냅샷에는 API 호출 예산을 차감하지 않는다. 네트워크에 실제 보낸 실패·결과 불명 요청은 1회를 사용한 것으로 유지한다.

스킬도 최종 답변 전 현재 작업의 성과를 연결하도록 보강했다. 재시도 요청만으로 보고 범위를 좁게 해석하지 않고, 검증이 완료되면 같은 목표의 앞선 구현과 짧게 연결한다. 이는 Codex의 작성 지침이며 모델 판정이나 네이티브 훅을 통한 강제 보장은 아니다.

## 실제 API 비교와 정책 재생

사용자가 추가 30회 비교 평가를 허용한 후 **기존과 동일한 비식별 사례 30개**를 각 1회 평가했다. 새로운 대화 자료는 추가하지 않았으며 재시도는 없다.

입력 72,002토큰, 출력 5,264토큰. 기존 동일 세트는 입력 63,212·출력 4,724토큰이었다. 여섯 번째 질문 때문에 토큰 비용이 늘었다. API 왕복 측정은 182–487ms, 합계 6,325ms였다.

| 구분 | 이전 | 수정 질문·정책 실제 API | 최종 정책 저장 판단 재생 |
| --- | --- | --- | --- |
| 정상 실제 19개 | 정상 4·보류 14·보완 요청 1 | 정상 16·보류 3·보완 요청 0 | 동일 |
| 실제 보고 누락 2개 | 둘 다 놓침 | 둘 다 놓침 | 새 사례 1개 내부 검토·기존 대조 1개 놓침 |
| 명시적 전환·복귀 2개 | 둘 다 보류 | 둘 다 보류 | 동일 |
| 가상 누락 3개 | 내부 검토 2·보류 1 | 내부 검토 2·보류 1 | 동일 |

기존 좁은 질문 대조는 보류→정상 통과, 가상 좁은 질문은 보류 유지였다. 정답 없는 탐색 2개도 보류 유지했다. `silent`는 사용자 개입이 필요 없다는 정책 결과이며 실행 성공을 뜻하지 않는다.

H11의 불필요한 보완 요청은 사라졌다. 새 질문에서 관련 누락 점수는 0.73→0.34였다. H19는 근거 0.79·성과 부정 0.55여서 정상 개입 기준에는 미달한다. 명시적인 결과 설명 요청을 근거로 한 최종 정책 재생에서만 `abstain → review`로 바뀌었다.

**이후 바꾼 것은 정책 분기뿐이다.** 새 30회 결과의 질문 스키마와 사례별 입력 해시가 최종 코드와 일치하는지 검사한 뒤 저장 판단을 재생했다. 변경 후 새 API 호출이나 실제 정정 성공을 주장하지 않는다. 이 재생은 개발 결과이고 추가 독립 검증이 필요하다.

C02는 재요청한 조회 성공을 보고하면서 앞선 설치·복구 성과와의 연결을 빠뜨린 사례다. 새 질문에서도 놓쳤다. 이 유형은 최종 작성 지침으로 보완했지만 자동 탐지 해결을 입증하지 못했다. H14·H17의 전환·복귀 내부 갱신도 여전히 보류된다.

## 검증과 파일

- Python 오프라인 검사 **149개 통과**. 새 검사 23개는 부모 성과 보존·별개 목표 제외, 길이 한도·미완료 조건 보존, 모순 검토, 질문 포장·훅 입력 배제, 확률 합산, 실제 호출 예산, 명시적 결과 질문의 제한, 설치 설정 보존을 다룬다.
- 샌드박스 설치 성공. 외부 전송은 기본 비활성으로 확인한다.
- 판단 코드·스킬·출처 문서를 **전역 설치에 반영했다**. 소스·설치본·manifest 해시가 일치하고, 설치본 핵심 검사 **10개 통과**. 네이티브 목록에서 기존 포함 훅 **10개 모두 enabled/trusted**, 경고·오류 없음.
- 설치기에 `--preserve-config`를 추가했다. 실제 `config.json`과 `hooks.json`이 변경 전과 바이트 단위로 같다. 전송 동의·모드·기존 지침·훅 신뢰를 변경하지 않는다. 전송 설정도 다시 쓰는 기존 명령은 자동 승인 검토에서 차단됐고, 설정 쓰기를 제외한 갱신 경로로 승인·적용했다.
- 직전 대화에서 실제 Stop continuation의 수신은 관찰했다. 정상 보고에 대한 오탐이어서 정정 없이 종료했다. 유효한 누락을 실제 자동 정정한 사례는 아직 관찰하지 않았다.
