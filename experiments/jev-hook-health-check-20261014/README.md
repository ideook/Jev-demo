# Belay / Skill Picker 점검, 2026-10-14

Skill Picker의 설치와 카탈로그 조회는 정상이다. Belay는 실행 가능한 상태이지만,
완료 판단에 쓰는 근거를 수집하는 과정에서 세 가지 사각지대가 재현됐다.
현재 Belay는 `shadow: true`이므로 판단을 기록하고 알리며 작업을 차단하지 않는다.

## 환경과 설치 상태

- Windows, Python 3.12, Node 24.18.0, Codex CLI 0.160.0, 날짜 기준 Asia/Seoul.
- 실제 Codex `hooks/list`: Belay, Skill Picker, Jev Explore 모두 `enabled: true`,
  `trustStatus: trusted`. 경고와 로딩 오류는 없다. 합성 Jev demo 훅은 비활성 상태다.
- 두 훅은 별도 Jev 플러그인 패키지가 아니라 사용자 전역 훅으로 설치돼 있다.
- Belay 설치 파일 6개와 Skill Picker 핸들러는 현재 저장소 파일과 SHA-256이 일치한다.
  `jev-explore` 스크립트와 `typesafe-ai/SKILL.md`도 일치한다.
- Belay: 완료 임계값 `0.75`, `shadow: true`, `log: true`, 모델 `jev-1.13.0`.
- Skill Picker: 신뢰도 임계값 `0.8`, 모델 `jev-latest`.
- 두 설정 모두 외부 평가 플래그가 켜져 있고 프로세스 환경의 자격증명을 찾았다.
  비공개 환경 파일은 존재하지 않지만 현재 프로세스 환경에서 키를 찾으므로
  그것만으로 인증 실패라고 판단하지 않았다. 키를 출력하거나 복사하지 않았다.

## Belay 근거 수집 재현

[합성 재현 스크립트](belay-evidence-probes.mjs)는 외부 API, 실제 파일 수정,
실제 대화 전송 없이 Codex 기록 형식으로 입력을 구성한다.

```powershell
node experiments/jev-hook-health-check-20261014/belay-evidence-probes.mjs
```

| 입력 | 기대 | 실제 | 영향 |
| --- | --- | --- | --- |
| 수정 후 성공한 `npm test` | 새 검사 1 | 새 검사 1 | 정상 대조군 |
| 수정 후 성공한 `python -m unittest` | 새 검사 1 | 새 검사 0 | 검사 성공을 놓쳐 불필요한 완료 경고 가능 |
| 수정 후 `Get-Content`로 과거 pytest 성공 로그 읽기 | 새 검사 0 | 새 검사 1 | 검사 재실행 없이 완료 검증을 통과시킬 수 있음 |
| `Set-Content`로 파일 수정 | 수정 1 | 수정 0 | 파일 변경이 있어도 완료 평가를 건너뛸 수 있음 |

대조군 1개는 일치하고 문제 사례 3개는 불일치한다. 재현 스크립트 종료 코드 `1`은
이 미해결 문제를 표시한다. `codex-evidence.mjs`의 수정 감지와 검사 분류가 원인 경로다.
설치된 코드와 저장소 코드가 일치하므로 설치본에도 같은 수집 동작이 적용된다.
이번 점검에서는 핸들러, 전역 설정, 기존 작업 변경사항을 수정하지 않았다.

  루프백 모의 서버만 제한 밖에서 재실행했다.

- `git diff --check` 통과. macOS 실행은 하지 않았다.

## 실제 API와 자동 실행의 확인 한계

합성 실호출 진단은 처음에 자동 승인 검토에서 거절됐다. 이후 사용자가
"실호출 진단 허용, 최대 4회"라고 승인해 준비한 두 요청을 실행했다.
실제 HTTP 요청은 **총 2회**, 각 진단 1회였으며 재시도는 없었다.

- Skill Picker: 승인된 합성 요청과 스킬 138개의 이름·설명만 전송했다.
  설치된 핸들러의 요청·응답 검증을 사용했고, `jev-explore` 선택,
  신뢰도 **1.0**, 선택 확률 **1.0**, 추천용 `additionalContext` 생성을 확인했다.
  설정 모델 `jev-latest`의 실제 응답 모델은 `jev-1.13.0`이었다.
  요청 소요 시간은 **312 ms**, 사용량은 입력 **14,046**, 출력 **1,437** 토큰이었다.
- Belay: 승인된 합성 retry 작업, 합성 완료 문장, 수정 수 1, 빈 검사 목록과
  고정 질문만 전송했다. 실제 응답 모델은 `jev-1.13.0`, 질문 **4개**의 답을 받았다.
  완료 주장 **0.98**, 검사 성공 주장 **0.96**, 검증 필요도 **0.95**로,
  완료 임계값 **0.75**에서 `would_block: true`, `false_claim: true`였다.
  유지된 `shadow: true` 설정에서는 경고 대상이며 작업을 차단하지 않는다.
  요청 소요 시간은 **232 ms**, 사용량은 입력 **690**, 출력 **99** 토큰이었다.
- 두 진단은 저장된 본문과 전송 본문의 일치를 확인하고 다른 주소로의 리디렉션을
  금지했다. 인증 키는 기존 환경에서 읽어 인증 헤더에만 사용했고 기록하지 않았다.
  실제 대화, 소스, 스킬 본문과 경로는 전송하지 않았다.

이 결과는 두 종류의 합성 진단에 대한 실제 API 응답과 판단 확인이다.
Skill Picker의 신뢰도 1.0은 이 한 사례의 모델 출력이며 일반적인 정확도 보장이 아니다.
Belay 진단은 Stop 핸들러를 실행하지 않았고 전역 설정·결정 로그를 수정하지 않았다.
아래의 자동 실행 확인 한계와 앞서 재현한 근거 수집 문제 3개는 그대로 남는다.

동일 날짜의 기존 설치 검증 기록에는 Belay 실응답 4개와 Skill Picker의
`frontend-design` 선택, 신뢰도 `0.81`이 있다. 기존 Belay 결정 로그에는
2026-10-14 **11:03:23 KST**의 실제 Codex 세션과 연결된 shadow 판단 1건이 있다.
이 파일을 현재 읽어 확인했지만, 그때의 성공을 지금 새로 호출한 결과로 취급하지 않는다.

현재 채팅에서 Skill Picker 추천이 모델에 전달된 기록은 확인되지 않았다.
추천 없음과 조용한 실패를 구분할 상태 로그가 없으므로 자동 추천 전달 성공을
단정할 수 없다. Belay의 현재 채팅 Stop 실행은 이 턴이 끝나야 관찰할 수 있다.
훅 등록·신뢰 상태와 핸들러 검사만으로 자동 실행 전체 성공을 선언하지 않는다.
이는 [공식 Hooks 문서](https://learn.chatgpt.com/docs/hooks)의 등록·신뢰·이벤트 구분과도 일치한다.

## 결과와 다음 확인

로컬 증거는 `.runtime/experiments/jev-health-check-20261014/`에 보관한다.
`native-catalog.jsonl`, `python-tests-local-temp.txt`, `upstream-tests-unrestricted.txt`,
`evidence-probes.jsonl`은 현재 점검 결과다. 자격증명과 실제 대화 본문은 보관하지 않았다.
승인 후 실호출 결과는 `live-picker-result.json`, `live-belay-result.json`에 저장했다.

승인용 `proposed-live-requests.json`에는 인증 헤더 없이 정확한 전송 예정 본문을 저장했다.
대상은 `https://api.typesafe.ai/v1/systemone`이고, 합성 평가 두 종류다.

- Skill Picker: "이 저장소에서 자동 스킬 선택이 구현된 파일을 찾아 관련 코드를 설명해 줘."
  및 현재 스킬 138개의 이름·설명. 스킬 본문, 경로, 소스와 실제 대화는 포함하지 않는다.
  HTTP 요청 최대 1회.
- Belay: 합성 retry 작업, 합성 완료 문장, 수정 수 1, 검사 목록 없음 및 고정 평가 질문.
  정상 시 HTTP 요청 1회, 통신 오류나 429/5xx에는 재시도를 포함해 최대 3회.

사용자 승인 후 두 진단을 실행했고 실제 HTTP 요청은 합계 2회였다.
승인 한도 4회를 넘지 않았으며 정상 API 사용량이 발생했다.
Belay의 근거 수집 사례 3개는 실호출 승인과 별개로 수정 및 회귀 검증이 필요한 상태다.
